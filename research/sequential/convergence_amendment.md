# Validation-convergence amendment, 2026-09-26

This amendment is made after inspecting the first two initial validation learning curves, before loading or evaluating the new disjoint confirmation cohort. Some original exploratory-test diagnostics have already been inspected; those remain explicitly exploratory. The amendment is justified by nonconverged validation curves, not by exploratory-test effect signs.

Both ALL seed 11 and ALL seed 29 selected epoch 5, the original cap. Seed 11 validation first-observed-attempt NLL decreased from 0.688089 to 0.660257, 0.638313, 0.626796, and 0.613747. Seed 29 decreased from 0.690043 to 0.658505 and reached 0.621610 and 0.612075 at epochs 4 and 5. Improvements near the cap exceed 0.009 NLL, which motivates giving both loss modes equal opportunity to converge.

Keep the original architecture, training/validation students, preprocessing, seeds 11/29/47, optimizer, learning rate, batch size, gradient clip, and TBPTT length. Before final fitting, set the two unknown event embeddings (indices 1 and 2) deterministically to zero; the unknown query embedding (index 0) is also zero. These indices never occur as training events/queries and remain zero without gradient updates. Unknown events are still processed through the recurrent transition with zero input. This corrects random untrained out-of-vocabulary representations identified by independent code review; it changes no training-known event or query initialization. Quantify pairs containing unknown-history events in coverage output.

Train all six final models afresh from their fixed seeds, with a maximum of **30 epochs** and early stopping after **four consecutive epochs without validation first-attempt NLL improving by at least 0.0001**. Retain the checkpoint with the absolute smallest validation first-attempt NLL seen. The minimum-improvement criterion governs patience, not which observed checkpoint is selected. No hyperparameter search or test-based architecture change is allowed. Independent seed workers may run in parallel with two CPU threads each, at most three workers/six threads; this does not change their batches, RNG seeds, losses, or optimizer updates.

Five-epoch results/checkpoints are retained as exploratory artifacts. Final fits live in `research/sequential/validation_converged/`. Fit every final model and freeze checkpoint hashes before opening the new confirmation input. Export final validation predictions first for the application's threshold lock. Only afterward evaluate the confirmation cohort once with the frozen checkpoints; never use its labels for epoch selection, threshold selection, calibration, or architecture changes.

The original `protocol.md` remains the source for all other methodological choices. Clarifications in `implementation_notes.md` record window-local optimization weights and untrained unknown-history embeddings. This is a prospectively locked confirmation analysis conditional on an existing exploratory phase, not a claim that the complete study was preregistered externally.
