# Literature audit artifacts

This directory separates authored synthesis from downloaded third-party evidence. It contains no learner-level data and no model-fitting experiment.

Safe authored files for a conservative source-only package:

- `gap_audit.md`, `supplementary_gap_audit.md`, `revision_information_gap.md`, this file.
- `references.bib`, `sources.json`, `supplementary_sources.json`, `revision_sources.json`.
- `build_sources.py`, `fetch_primary.py`, `fetch_code_evidence.py`.
- `download_manifest.json` and `code_manifest.json`: retrieval URLs, hashes, revision identifiers, paths and status, without downloaded source contents.

Exclude `papers/` (PDFs and extracted full text), `code/` (third-party source), raw `*_metadata.json` records, raw `*_bib.txt` publisher exports, and raw `*_tree.json` repository trees from that package. Their inclusion requires a separate license/redistribution decision. Metadata synthesis and citations can remain; references to absent archived evidence files are provenance pointers, not runtime dependencies.

To regenerate the authored 17-source ledger, from the workspace root:

```powershell
python research/literature/build_sources.py
```

This uses only Python standard-library `json` and `pathlib`; it reads `download_manifest.json`, `code_manifest.json`, `supplementary_sources.json`, and `revision_sources.json`. It makes no network calls and executes no downloaded code. No bibliography auto-generation is performed: bibliographic fields were manually verified against primary records.

`fetch_primary.py` requires `requests` and PyMuPDF (`fitz`) and retrieves public PDFs, validates the PDF signature, extracts text and hashes files. **Its current main entry point covers only the original eight PDFs and overwrites the download manifest. Do not run it as a full restore of the expanded archive.** Later targeted retrievals used its `fetch((id, url))` helper and merged results into the existing manifest. The manifest records the authoritative retrieval inventory, including unsuccessful requests.

`fetch_code_evidence.py` requires the GitHub CLI (`gh`) and Python standard library. It reads pinned repository files via `gh api`; it never imports or executes downloaded code. It writes third-party evidence under `code/` and rewrites `code_manifest.json`. Re-running it is an optional online evidence refresh, not required to reproduce the synthesis. No fit, test score or model result is generated by either retrieval script.

Source status is explicit: a metadata-only artifact or inaccessible paper must not be reported as a reproduced fulltext result. PDF page anchors use the archived version's one-based pages and can differ from publisher pagination. The four requested revision-branch sources are recorded in `revision_sources.json` and the 17-entry main bibliography. SETR-PKT's unresolved conference-program announcement is not included as a published paper.
